The problem

A broken sensor sends wrong data, and nobody notices.

That data slips into forecasts and disaster warnings. Flood, cloudburst and heatwave alerts are only as good as the readings behind them.

In Haryana, 20 IMD weather stations stopped sending usable data for months before anyone noticed. More stations without automatic checking just means more bad data on the map.

Proposed solution

Six steps from a raw reading to a repair ticket.

Physics handles the easy cases first, so the AI only has to learn the rest. That keeps false alarms low.

Collect

The station sends temperature, pressure and humidity every minute.

Quick check

The station itself blocks impossible values: out of range, sudden jumps and stuck readings.

Physics check

Do T, P and RH agree with each other and with nearby stations? No training needed.

AI check

AI learns each station’s normal pattern to spot sudden spikes and slow drift.

Decide

Real weather hits neighbours too. A broken sensor is alone. That is the test.

Alert

A repair ticket says which sensor, what is wrong, why, and gives a corrected value.

Two independent checks

Is it a real heatwave or a broken sensor?

Same station, same hour, two different causes. The bright line is the station, the dashed line is what its neighbours within 100 km say it should read. Both cases are scored by the working engine.

Check 1 · Physics

T, P and RH are linked. If temperature jumps but humidity does not change to match, the sensor moved, not the air.

Check 2 · Neighbours

Stations within 100 km usually agree. If only one station goes strange, it is that station’s sensor.

What is new

Four ideas that set it apart.

Physics first, AI second

Physics handles the easy cases, so the AI learns only the rest. Fewer false alarms.

Every alert is explained

Maintenance teams see the reason, not just a score.

Flagged: humidity reading jumped while 4 nearby stations stayed normal.

Real extremes are not deleted

Two independent checks separate a real heatwave from a failing sensor. Data is flagged with a confidence score, never removed.

Works on the station itself

A tiny AI model, under 100 KB, runs on a low-cost chip and flags bad data before it is sent.

The working prototype

Five layers, one probability, one explanation.

Every layer is causal, so the same code scores a stored archive or a live one-minute stream. A learned fusion stage decides how much to trust each layer, so real weather is kept and faulty sensors are flagged.

LAYER 1

Quick check

Range, jump, stuck and missing-packet rules from WMO No. 8. Near-certain errors raise an alert at once.

LAYER 2

Physics

Temperature and humidity must imply a steady dew point (Bolton, 1980). Air moisture cannot jump in minutes.

LAYER 3

Temporal AI

IsolationForest and a neural autoencoder learn each station's normal daily pattern from 17 residual features.

LAYER 4

Neighbours

Compares the station with everything within 100 km. Stations already flagged are left out, and disagreement between neighbours widens the yardstick.

LAYER 5

Fusion

A gradient-boosted model, trained on injected faults, turns all evidence into one fault probability per minute.

Root cause

Spike, sudden jump, slow drift, stuck value, noise burst, communication error or power glitch.

Confidence and severity

Every alert carries a probability and a High, Medium or Low severity.

Corrected value

What the sensor should have read, estimated from neighbours, or from its own history when none exist.

Sensor health

A 0 to 100 score per sensor, its drift rate, and the days until it leaves tolerance.

Measured results

Scored on data with faults injected at known times.

This is the evaluation method in the problem statement. Three independent test runs, 57 stations, 4 days each, 550 injected faults in total. Half of the spikes, jumps, drifts and noise bursts are subtle, near the sensors' accuracy tolerance.

Run it yourself

Fully executable, with examples.

Python 3.9 or newer. The only dependencies are numpy, pandas, scipy and scikit-learn.

# install
pip install -r requirements.txt

# see alerts on a simulated network with injected faults
python -m trinetra demo

# the 55 C example from the problem statement, with the full explanation
python examples/quickstart.py

# feed one minute at a time, as a live system would
python examples/stream_demo.py

# run on your own CSV files
python examples/custom_csv.py

# reproduce the accuracy table, then rebuild this website's data
python -m trinetra evaluate
python -m trinetra export

# the ESP32 edge layer (plain C++, compiles anywhere)
g++ -std=c++11 edge/edge_qc_test.cpp -o edge_test && ./edge_test

Feasibility and viability

It can start working from day one.

Data already exists

IMD runs about 1,008 stations that record T, P and RH. Free public archives (NOAA, Meteostat) add years more.

Easy to test

We add fake faults (spikes, stuck values, drift) to clean data at known times, then count how many we catch.

Works from day one

Physics checks need no training. The AI layer improves results over time.

Low cost

Runs on the kind of low-cost chip already used in stations. Open-source, no licence fees.

Risk
How we handle it
A real 50 °C heatwave can look like an error
Real heat passes both the physics and neighbour checks. Data is only flagged with a confidence score, never deleted.
Slow drift (0.1 °C a month) is hard to see
Compare each station with its own past years, and watch the daily pressure cycle.
Some stations have no neighbours nearby
Use the physics check alone and show a lower confidence score.
The station chip has very little memory
Tiny model on the station; the heavy AI runs on the central server.

Impact and benefits

Cut the time between a sensor going wrong and a person being told.

Main user: the IMD network maintenance and forecasting team. Also helps disaster management authorities, farmers’ weather advisories and aviation. Today a broken station can go unnoticed for months. With TRINETRA the fault is flagged automatically, with a repair ticket naming the sensor and the problem.

SOCIAL

Safer warnings

Flood, cloudburst and heatwave alerts are only as good as the data behind them.

ECONOMIC

Low cost

No new hardware, open-source, no per-station licence. Fewer wasted field visits.

ENVIRONMENTAL

Saves power

OPERATIONAL

Scales with growth

Mission Mausam adds stations faster than people can check by hand. TRINETRA keeps up.

The physics behind our checks

  • Bolton (1980) · formula linking temperature and humidity (vapour pressure)
  • Dai & Wang (1999); Hamilton et al. (2008) · pressure rises and falls twice a day by about 1–1.5 hPa, a built-in clock to test barometers
  • WMO No. 8 · comparing a station with its neighbours (buddy check)
